# Kontora styling conventions

Kontora is a **styling-only** design system: tokens, fonts and a compiled Tailwind build. It ships no importable components: `window.Kontora` is an empty namespace. Build the markup yourself and dress it with the vocabulary below.

## Setup

No provider and no wrapper. Import `styles.css` once; everything else follows.

Theme is an attribute on the root element. Dark is the default from `:root`; light is selected by `[data-theme='light']` on `<html>`. Set `document.documentElement.dataset.theme = 'light'` to switch, and keep `color-scheme` in step so form controls follow.

## The idiom

Tailwind utility classes, plus `var()` for anything the utility set does not cover.

Every color token is a bare channel list (`--tx: 221, 225, 238`), not a color, so utilities take alpha modifiers: `bg-surface-900/70`, `border-accent/30`.

| Family | Classes | Use |
|---|---|---|
| Surfaces | `bg-surface-deep`, `-950`, `-frame`, `-rail`, `-900`, `-850`, `-800`, `-700`, `-600` | deep = page well, 950 = app ground, frame/rail = chrome, 900/850/800 = cards and popovers, 700/600 = muted fills |
| Borders | `border-edge-card`, `-input`, `-hover`; `border-surface-700`; `text-edge-faint` | card = default 1px edge, input = form fields, hover = lifted, faint = barely-there divider |
| Accent | `bg-accent`, `text-accent`, `text-accent-bright`, `text-accent-fg`, `border-accent` | `accent-fg` is the readable foreground on an accent fill |
| Semantic | `bg-ok`, `bg-warn`, `bg-err`, `text-ok`, `text-warn`, `text-err`, `text-review` | success, caution, failure, human-review |
| Text | `text-tx`, `-tx-hi`, `-tx-2`, `-tx-3`, `-tx-4`, `-tx-log`, `-tx-faint` | tx = body, hi = emphasis, 2 to 4 step down to muted, log = terminal output |
| Status hues | `text-st-open`, `-st-progress`, `-st-paused`, `-st-review`, `-st-done`, `-st-cancel` | ticket lifecycle; also `bg-st-done/10` and similar tints |
| Type | `font-sans` (DM Sans), `font-mono` (JetBrains Mono) | mono carries IDs, branches, paths, logs and terminal output |

**The compiled utility set is not complete.** `_ds_bundle.css` was generated by scanning kontora's own markup, so only the class + alpha combinations kontora uses have rules. `bg-accent-dim` and `text-surface-900`, for example, do not exist. For anything outside the table, reference the token directly instead of guessing a class:

```css
background: rgba(var(--surface-850), 0.6);   /* rgb channel tokens */
color: hsl(var(--st-done) / 1);              /* --st-* are HSL triples */
```

Set `[data-pipe-color="indigo|cyan|amber|green|rose|mauve|none"]` on a container to get a per-pipeline hue at `hsl(var(--pipe-h) / 0.4)` in its subtree.

## Where the truth lives

`styles.css` and its imports are the whole system. Read `tokens/colors.css` for the palette in both themes, `tokens/status.css` for the status and pipeline hues, `tokens/base.css` for the globals, and grep `_ds_bundle.css` to confirm a utility class exists before using it.

## Example

```jsx
<div className="bg-surface-900 border border-edge-card rounded-lg p-4 flex items-center justify-between">
  <div>
    <div className="text-tx-hi text-sm font-medium">Rewrite the scheduler</div>
    <div className="text-tx-3 text-xs font-mono">ticket-142 · feat/scheduler</div>
  </div>
  <span className="text-st-done text-xs bg-st-done/10 rounded-md px-2 py-1">done</span>
</div>
```
